## 一、任务变化对比

| 维度 | 旧任务（v1） | 新任务（v2） | 变化 |
|---|---|---|---|
| 登录 / 用户 | ❌ 不负责 | ✅ 注册/登录、JWT、Google OAuth、CurrentUser | **新增** |
| 对话链路 | ✅ 聊天 UI、Conversation/Message、历史、SSE | ✅ 保留：创建/读取 Conversation、提交消息、流式展示、保存历史 | 基本不变 |
| 发布 / 开放平台 | ✅ API 渠道、API Key、对外 Agent API、TS SDK | ✅ 保留：发布 Agent、生成 API Key、公开 Agent API 调用（SDK 是否仍归你**待确认**） | 需确认 |
| 工作量 | 中 | **大**（认证是全组的地基，别人都依赖你） | ↑ |

**关键认知**：你的模块是全组最上游。陈弘毅的 Agent 绑定、管逸恬的知识库权限、朱曾亨的插件权限、博美佳的工作流权限，全部要消费你产出的 `CurrentUser` 和鉴权错误格式。所以你的调研要**优先产出契约草案**，而不是先埋头写 UI。

## 二、新任务全景（把 11 步代码块归纳成 4 块）

```
1. 进入注册或登录页面
2. 输入用户名密码，或选择 Google 登录          ┐
3. 后端校验并创建或查找用户                    ├─ A. 认证与用户
4. 生成 JWT 并返回 CurrentUser                ┘

5. 用户进入聊天页面                           ┐
6. 创建或读取 Conversation                    ├─ B. 会话与历史
9. 保存 Message 历史                          ┘

7. 将消息提交给 Runtime                       ┐
8. 接收并展示流式结果                          ├─ C. 流式对话
                                             ┘

10. 发布 Agent 并生成 API Key                 ┐
11. 通过公开 Agent API 调用                    ├─ D. 发布与公开 API
                                             ┘
```

## 三、调研问题清单（每块要回答的核心问题）

### A. 认证与用户（新增，最优先）

**技术问题：**
- [ ] NestJS 鉴权怎么做？Passport + `@nestjs/passport` + `passport-jwt` 是标准组合，本地策略（用户名密码）和 JWT 策略各是什么角色？
- [ ] 密码怎么存？bcrypt 的 saltRounds 取多少？为什么不能明文/MD5？
- [ ] JWT 结构：payload 放什么（userId、email、exp）？secret 放 `.env` 的哪个变量？过期时间设多长？要不要 refresh token（MVP 建议不要，先砍需求）？
- [ ] Google OAuth 两种方案的区别：前端拿 code 后端换 token（推荐）vs 纯前端拿 id_token 传给后端验证。国内网络访问 Google 的坑怎么处理（开发期挂代理 / 提供用户名密码作为降级方案）？
- [ ] `CurrentUser` 长什么样？用什么装饰器（`@CurrentUser()` 自定义 decorator）注入到 controller？
- [ ] Guard 机制：`@UseGuards(JwtAuthGuard)` 怎么工作？哪些接口公开（`@Public()`）、哪些必须登录？
- [ ] Prisma 的 User 模型：id、username、passwordHash、googleId、avatar、createdAt……和其他模型（Agent、Conversation）的外键关系怎么设计？

**产出：**
- 认证流程图（注册 → 登录 → 发 JWT → 带 token 请求 → Guard 校验）
- User 表 Prisma schema 草案
- 鉴权错误格式草案（401 未登录 / 403 无权限，统一 JSON 结构）

### B. 会话与历史

- [ ] Conversation 和 Message 的表结构：Message 外键指向 Conversation 和 User；content、role（user/assistant）、createdAt、token 消耗？
- [ ] 「进入聊天页面」是新建会话还是恢复上次会话？会话列表接口（GET /conversations）+ 消息分页（游标分页比 offset 好）？
- [ ] 软删除还是硬删除？「删除会话」要不要进 MVP？
- [ ] 前端状态：React Query / SWR 还是手写 useEffect？消息列表的乐观更新怎么做？

### C. 流式对话（SSE）

- [ ] SSE vs WebSocket：为什么打字机效果选 SSE（单向、HTTP 原生、自动重连）？
- [ ] 后端：NestJS 里 SSE 怎么实现（`@Sse()` 装饰器 / Observable）？事件类型拆分：`message_start` / `delta` / `message_end` / `error`？
- [ ] 前端：`EventSource` 的限制（不能带自定义 header → token 怎么传？query 参数 or cookie）；fetch + ReadableStream 方案对比（fetch 方案可带 Authorization header，**推荐调研重点**）。
- [ ] 中断生成：用户点「停止」怎么通知后端（AbortController → 后端 AbortSignal）？
- [ ] 和王一恒的 Runtime 对齐：他吐出来的 SSE 事件格式长什么样？你做透传还是加工？

### D. 发布与公开 API

- [ ] 「发布」动作改什么状态？Agent 的 status 字段（draft → published）？
- [ ] API Key 生成：用什么算法（crypto.randomBytes → 前缀如 `mk-` + 随机串）？库里存明文还是哈希（哈希）？_sk 前缀显示只展示一次怎么设计？
- [ ] 公开 API 路径：`/v1/agents/:agentId/chat`？Bearer 认证和 JWT 认证是两套 Guard，怎么共存？
- [ ] 公开 API 的限流和配额（MVP 可以只做文档记录，不做实现）？
- [ ] TS SDK（packages/sdk）是否仍归你？若归：SDK 就是把 `/v1` 接口包一层 fetch + SSE 解析，调研 `@microsoft/fetch-event-source` 之类的库。

### Week 2 验收标准（组长定的，照条自测）

1. **两种登录方式均可进入系统，登录态可读取和退出**

2. **网页聊天与公开 API 均能从同一 Runtime 获得流式响应**
   - [ ] 网页聊天页发消息，SSE 打字机效果出字
   - [ ] 用 API Key + Bearer 调公开流式接口（curl / Postman），同样收到 SSE 流
   - [ ] 两者走的是**后端同一条 Runtime 调用路径**（写代码时抽成一个内部 service，别复制两份）
3. **密钥只放环境变量**
   - [ ] JWT secret、Google client secret、API Key 加密 key 全部进 `.env`，`.env.example` 只留占位符，不硬编码在代码里

## 七·补、Week 2 按天执行清单（本周照做）

> 今天是周一 10.12。原则：**先跑通主线，再抠细节**；Google OAuth 卡壳就先跳过，用用户名密码保证验收条 1 的前半句成立。

**周一（今天）— 调研收尾 + 契约先行**
- 上午：过补课清单 P0（TS 基础 + React useState/useEffect），只看够用的
- 下午：读参考仓库 momo040611/MiniCoze @ test/v0.2 的 auth 模块，摘抄结构

- 顺带 Prisma 接上数据库，跑通第一条 migrate

**周二 — 认证主体（验收条 1 的核心）**
- Prisma 建 User 模型（username、passwordHash、googleId、avatar）
- 实现 `POST /auth/register`（bcrypt 哈希）和 `POST /auth/login`（校验后签 JWT）
- 用 Postman 跑通：注册 → 登录 → 拿 token → 带 token 请求一个测试接口

**周三 — Guard、CurrentUser、退出、登录页**
- 自定义 `@CurrentUser()` 装饰器 + `JwtAuthGuard`；`@Public()` 装饰器标注公开接口
- 退出登录：前端删 token 即可（MVP 不做服务端黑名单）
- 登录/注册页面 UI（React，先把表单能提交、token 存起来、刷新后还在）
- 时间富余就接 Google OAuth，不富余推到 Week 3

**周四 — 会话与聊天页面（验收条 2 前半）**
- Prisma 建 Conversation / Message 模型
- 接口：创建会话、会话列表、读历史消息（游标分页）
- 前端聊天页：左侧会话列表 + 右侧消息区 + 输入框

**周五 — SSE 流式 + 公开 API（本周最难的一块，留整日）**
- 后端抽一个 `ChatService`：入参（agentId、消息、user），内部调 Runtime（本周先用 Mock Provider 吐假流），返回 SSE 流——**网页聊天和公开 API 都调它，满足"同一 Runtime"验收条**
- 网页端：fetch + ReadableStream 消费 SSE，打字机渲染
- 公开端：`POST /v1/agents/:id/chat`（Bearer API Key 鉴权），返回同样的 SSE
- API Key：crypto 随机生成、库里存哈希、展示一次

**周末 — 自测验收 + 对齐 + 提交**
- 照上面 3 条验收标准逐条打勾
