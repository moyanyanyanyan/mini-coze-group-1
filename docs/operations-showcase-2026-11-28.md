## 实际发现与处理

1. 后台进程缓存了旧 Prisma 文件类型，导致 Markdown 上传 500。重启现有后台后恢复，十种文件类型均能进入实际处理流程。
2. 供应商偶尔返回空正文且终态为完成。空回复进入历史后会导致记忆预览和下一轮聊天被 Runtime 的非空约束拒绝。已改为跳过这种不完整问答对，保留原始消息和运行记录；回归测试先复现失败，再验证修复。
3. 首页把所有文件失败笼统显示成“向量化失败”。已复用文件详情的真实阶段文案，解析失败、切片失败等会按实际阶段呈现。

图片 OCR 当前缺少 Worker 内部凭证，图片样本真实失败并显示 `OCR_CONFIGURATION`；损坏 PDF 是刻意上传的失败样本。没有将这两份文件伪造为处理成功。旧的 `POST /api/conversations/:id/messages` 仍是历史占位入口，本次生成真实聊天全部使用当前页面相同的流式接口或 `/api/v1/run`，没有使用该占位接口。
