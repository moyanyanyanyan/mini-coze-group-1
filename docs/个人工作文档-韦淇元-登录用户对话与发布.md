## 二、本周已完成工作

### 1. 后端：认证与用户模块（A 模块，已完成并实测）

- **Prisma 接入与 User 表**：接入 Prisma 6.19.3，建立 `User` 表（`id / email / passwordHash / createdAt / updatedAt`），迁移 `20261019123105_init_user` 已应用。
- **注册/登录接口**：`POST /api/auth/register`、`POST /api/auth/login`，密码使用 **bcryptjs**（cost=10）哈希存储；注册侧强制密码 MinLength(8)，登录侧仅非空校验（bcrypt 只取前 72 字节）。
- **JWT 认证闭环**：JWT 7 天有效期（无 refresh）；payload 为 `{ sub: userId, email }`；`JwtStrategy` 用 `payload.sub` 反查用户，查不到统一抛 `TOKEN_INVALID`。
- **凭证方案升级为 HttpOnly Cookie**：`access_token` 走 HttpOnly + SameSite=Lax Cookie（7d，path=/，生产 Secure），避免 token 落入 localStorage；新增 `POST /api/auth/logout` 清除 Cookie（path 与下发一致）。JWT 提取支持**双通道**（Cookie 优先，兼容 Bearer Header）。依赖 `cookie-parser` + CORS `credentials:true`。
- **`GET /api/auth/me` + CurrentUser 契约**：自定义 `@CurrentUser()` 装饰器；对外一律过 `toCurrentUser()` 转换，`passwordHash` 绝不出库。
- **安全设计**：用户不存在与密码错误返回同一错误（防账号枚举）。
- **统一错误体系**：错误码 + 统一错误响应格式（`common/` 目录），前后端共用契约。
- **e2e 测试**：`test/auth.e2e-spec.ts` 覆盖注册→登录→me→登出全链路；解决 jest 30 + ESM（@nestjs/passport、@nestjs/jwt 纯 ESM）在 CJS 下的加载问题并落盘 jest 配置。
