### 0.1 原页面内替换规则

- 沿用原运行管理页面和导航，不设置真实/Mock 模式，不新增独立 Runtime 页面。
- 实际 Agent、会话、知识库和文档替换原列表；真实调用的问答、状态、Token、耗时和事件进入原会话回放与执行链路面板。
- 某类资源或采集记录为空时保留原示例并标注“示例”；接口失败显示错误，不当作无数据。缺少的阶段耗时、文件字节数和检索过程在原位置明确标注示例或未采集。
- 示例不计入真实统计，不将示例检索或工具调用绑定成真实执行结果。Token 合计及峰值来自后端全量已报告 usage；列表时间筛选和成功率仅针对已加载记录，页面说明范围。
- 文档详情沿用原路径，实际记录末段使用 documentId；示例记录使用 taskId。
- 目录按接口分页加载元数据；最近调用默认 100 条，可加载更多。选中会话时仅加载该会话调用，消息读取最新 100 条并按 seq 正序显示。选中切片详情时读取该文档切片，在原界面分页展示。
- 刷新失败保留数据和上次成功时间并提示错误；401 返回登录页，403/404 清除失效详情。旧页面请求不会覆盖新页面结果。
- 当前页有处理中记录时每 5 秒刷新，不叠加请求；页面隐藏暂停，恢复可见后继续，记录结束后停止。

### 0.2 已实现查询接口

以下接口需要 JWT，只使用认证上下文中的当前用户，不接受客户端指定数据归属，不提供匿名 demo 绕过。

| 接口 | 参数与返回 |
| --- | --- |
| `GET /api/operations/overview` | Agent、会话、知识库、文档、处理中和失败文档数量，asOf |
| `GET /api/operations/agents` | q、status=DRAFT/ACTIVE/ARCHIVED、page/pageSize；Agent 分页和本人会话数 |
| `GET /api/operations/agents/:id/conversations` | q、page/pageSize；Agent 基本信息和本人会话分页 |
| `GET /api/operations/conversations/:id/messages` | page/pageSize；会话基本信息与消息分页；id 必须为 UUID |
| `GET /api/operations/knowledge-bases` | q、page/pageSize；知识库分页、文档数、可用切片数、处理中和失败文档数 |
| `GET /api/operations/knowledge-bases/:id/documents` | q、status=PROCESSING/READY/FAILED、page/pageSize；知识库基本信息和当前文档分页 |

成功响应使用 `{ code: 200, message: 'ok', data }`，分页 data 包含 `items/page/pageSize/total/asOf`。page 默认 1、最大 1000000；pageSize 默认 20、最大 100；q 去除首尾空格，最多 100 字。

列表按 updatedAt、id 倒序；消息按 seq、id 倒序选页，再转为正序返回。列表、总数和关联统计使用 RepeatableRead 事务一致性读取。现阶段不支持运行时间范围、来源或运行状态筛选。

可用切片数仅统计 READY 文档中 enabled=true 且存在向量的切片；知识库启停状态单独展示。所有聚合在后端完成，不加载文件原文、切片正文或向量进行列表统计。

文档信息来自上述知识库文档列表；切片复用 `GET /api/knowledge-bases/:id/documents/:documentId/chunks`，使用当前登录用户 ID 作为既有 workspaceId 参数。前端验证文档所属知识库与 URL 一致，后端原接口继续验证用户及父资源归属。

现有切片接口不支持停用知识库，原文档详情对此显示明确提示；未 READY 文档也不展示切片。没有为本次接入改变原业务接口行为。

### 0.4 operations 内部采集（第二阶段）

结构：`operations/collection/runtime-collector.service.ts` 包装既有 RuntimeClientService；`operation-records.service.ts` 负责落库、查询、统计与中断记录收敛。两个服务均由 OperationsModule 注册，采集客户端导出供 ChatModule 通过 useExisting 注入。与后端同进程启动，不新增服务端口，不改变 Runtime 服务地址，不需要独立启动命令。

接入覆盖通过 ChatService 使用该客户端的网页流式、公开 API 流式和非流式调用。其他直接访问 Python Runtime 的调用不在本次采集范围；mode 只表示 stream/run，不猜测平台/API 来源。

新增表 `OperationRuntimeRun`：runId、userId、agentId、conversationId、assistantMessageId、model、mode、status、startedAt/finishedAt、durationMs、firstTokenMs、inputTokens/outputTokens/totalTokens、errorCode、events、truncated。关联 Conversation，删除会话或用户时级联清理。聊天正文和提示词不复制到采集表。

| 新接口 | 内容 |
| --- | --- |
| `GET /api/operations/runtime/stats` | 当前用户采集总数、执行中数、有/无 usage 次数、已报告 Token 合计及峰值、客户端平均调用耗时 |
| `GET /api/operations/runtime/runs` | 当前用户采集记录分页；支持 conversationId（UUID）过滤，先检查会话归属 |
| `GET /api/operations/runtime/runs/:id` | 本人单次实际记录、事件、指标及当前消息保存状态 |

采集数据直接进入原概览卡片和 `/workspace/operations/agents/:agentId/conversations/:conversationId?run=:runId`。运行列表从已有消息读取相邻提问及回复，不在采集表重复保存正文。Token 卡片统计当前用户全部已报告调用，其余列表指标以页面已加载记录为范围。

采集规则：

- 原样调用底层 Runtime 客户端、原样转发每个 SSE 事件和错误，保留取消与迭代器关闭行为。只在开始和结束写库，不在每个 token 上执行数据库写入。
- 状态为 running/completed/failed/cancelled/interrupted，仅描述 Runtime 客户端观察结果。messageStatus 单独读取聊天消息数据库，不把 Runtime completed 冒充消息保存成功。
- Token 只记录 Runtime 返回的有效 usage；未知保持 null，页面称“已报告用量”，不宣称覆盖全部模型轮次。失败/取消响应没上报 usage 时不估算。
- durationMs 从进入底层客户端调用计时至该调用返回或迭代器关闭，不包含采集开始写库和聊天最终落库；firstTokenMs 仅对流式首个非空文本增量采集。工具耗时取客户端观察事件的间隔；非流式不补造耗时。
- 保存工具开始/结束、knowledge.result、最终结果摘要。工具输入、检索候选分数、模型服务商内部步骤未由协议输出，继续标记未采集；引用只表示上下文来源，不声称回答采用。
- 只在本轮结束后保存内存中的过程事件，因此进程崩溃可能丢失过程明细。每分钟把超过五分钟仍 running 的记录标记 interrupted，保留未知完成时间和耗时，不推断业务失败。阈值基于现有 Runtime 客户端 190 秒超时；若调整客户端超时，应同步调整阈值。
- 采集写库失败记录安全日志，不改变聊天结果。采集不能承诺零丢失；无记录不等于调用没有发生。
- 事件限制 100 条、总计 128 KiB、单条 16 KiB；嵌套深度、集合长度和字符串长度受限，超过限制有 truncated 标记。过滤常见敏感键、Bearer 凭据和已知内部密钥；不保存 HTTP 认证头。自由文本内容仍可能包含用户信息，仅本人可读。
- 调用中轮询；结束后若消息仍 pending/running，最多继续自动查询 30 秒，之后可手动刷新。不因业务消息长期 pending 而无限轮询。

部署顺序：应用新增迁移 `20261114120000_operations_runtime_collection`，运行 `pnpm --filter @minicoze/backend db:generate`，重新启动后端。迁移命令使用 `pnpm --filter @minicoze/backend prisma migrate deploy`，不需要 reset 或清空数据。Windows 若生成时提示 Prisma DLL 被占用，先停止本项目后端再生成并恢复启动。本地数据库已应用迁移；其他环境需自行部署该迁移。

验证：采集单测覆盖原样流式转发、终态 break、取消、异常、缺失终态、标识不匹配、脱敏、大小限制、采集失败不改变响应；数据库与 HTTP 联调使用受控 Runtime 验证真实落库、查询、用户隔离和级联清理，未调用付费模型；浏览器验证概览指标、事件详情和移动端布局。

### 0.5 Runtime 阶段摘要

- 新增 `runtime/observations.py`，以 `perf_counter()` 记录边界耗时。`service.py` 记录检索整体、上下文组装、无工具模型调用；`tool_loop.py` 记录各轮模型和工具执行。没有修改知识库与插件 Provider 或业务模块。
- 完成结果新增可选 `stages`；流式失败事件及非流式 HTTP 错误体也携带已记录的阶段摘要，不新增 SSE 事件类型。旧响应没有该字段时照常处理。
- 摘要字段：stageId、kind、startedAt、durationMs、status；按阶段附加 round、model、outcome、usage、chunkCount、toolCallId、toolName、errorCode。不保存提示词、模型正文或工具参数。逐轮 usage 未报告时保持缺失，不补零、不与整轮用量重复累计。
- 检索耗时为 Runtime 调用知识库接口的整体耗时；上下文切片数为实际组装的数量。模型计时覆盖流式读取及下游消费等待，不等同模型服务商计算时间。工具失败即使被后续模型恢复，阶段仍显示失败。
- Operations 校验白名单字段、脱敏后写入现有 events 的 `runtime.stage` 项，不新增表或数据库迁移。无效或超限摘要标记 truncated，不改变聊天原结果。

- 摘要在整轮结束时传回。取消连接或进程崩溃导致终态未送达时，不保证已完成阶段可恢复；不伪造后续阶段。历史调用不能补采，旧记录继续显示示例。

## 1. 目标与范围

运行管理用于查看 Agent 聊天和知识库文档处理的真实运行情况，定位异常，并返回原业务模块处理问题。

首版确定采用以下规则：

| 事项 | 决策 |
| --- | --- |
| 数据范围 | 仅当前登录用户；不做团队共享、成员角色或跨用户查看 |
| 业务范围 | Agent 聊天运行、知识库文件处理、聊天中的知识库检索 |
| 页面结构 | 保留现有概览、Agent、会话、知识库、处理任务详情结构 |
| 操作范围 | 运行管理提供查询；聊天重试和文档重试回到原业务模块 |
| 数据来源 | 实际执行时采集，后端持久化，前端通过接口查询 |
| 历史数据 | 不伪造缺失指标，不把旧消息反推为完整运行链路 |
| 保留策略 | 首版不自动清理运行记录；删除业务资源时同步处理其敏感历史内容，见第 8 节 |
| 默认时间 | 列表默认最近 30 天，可选最近 24 小时、7 天、30 天 |
| 今日口径 | 按 Asia/Shanghai 自然日；数据库统一存 UTC |
| 调度方式 | 沿用现有单实例执行方式，不新增消息队列或独立调度平台 |

默认查询 30 天不等于只保留 30 天数据。工作流运行、告警通知、费用估算和完整审计系统不在本次范围内。

## 3. 核心对象与状态

### 3.1 对象关系

- Conversation：一段连续聊天，包含多轮运行。
- Run：一次被后端接受的提问及其执行结果，与本轮用户消息和助手消息关联。
- Node：某轮运行中的检索、模型调用或工具调用。工具可以调用多次，不能只有一个 plugin 字段。
- Document：文档当前业务状态，决定是否可以检索。
- ProcessingTask：某个文档的一次处理尝试。重试创建新 taskId，不覆盖上次结果。
- TaskChunk：某次成功处理的切片快照，与当前可检索切片分开。

归属为：当前用户 → 会话 → 运行 → 节点；当前用户 → 知识库 → 文档 → 处理尝试。

### 3.2 运行状态

| API 状态 | 中文 | 含义 |
| --- | --- | --- |
| `running` | 运行中 | 已受理且未进入终态 |
| `success` | 成功 | 回答完成并保存成功，无已知节点异常 |
| `warning` | 完成但有异常 | 回答保存成功，但存在已恢复的工具失败等异常 |
| `failed` | 失败 | 执行失败、协议中断或最终回复保存失败 |
| `cancelled` | 已取消 | 用户停止生成，或请求连接取消导致执行被终止 |

允许 `running → success/warning/failed/cancelled`，终态不可被迟到事件覆盖。新一轮重试产生新的 runId。

取消需要记录 reason，区分用户停止和连接断开；当前协议无法区分时显示“请求已取消”，不能一律声称用户主动停止。

知识库未命中是正常业务结果，不直接导致 warning 或 failed。工具失败后仍完成回答可以为 warning；最终未完成回答则为 failed。

节点状态为 `pending/running/success/failed/cancelled/skipped`。未执行的节点不能显示成功或耗时 0；耗时未知为 null。没有采集到的节点不补造。

### 3.3 文档任务状态

任务状态为 `processing/ready/failed`，与文档现有状态映射。阶段沿用 `VALIDATING → EXTRACTING → CHUNKING → EMBEDDING → PERSISTING → COMPLETED`。

失败时保留实际失败阶段和错误；后续阶段显示未执行。重试只允许 FAILED 文档且知识库可用，沿用业务服务的原子条件更新。

## 4. 前端交互

### 4.1 页面与查询范围

| 页面 | 数据与交互规则 |
| --- | --- |
| 概览 | 今日异常按自然日查询；最新运行独立分页；累计 Token 明确为采集以来的已知值并展示采集覆盖情况 |
| Agent 列表 | 展示本人拥有的 Agent，汇总所选时间内本人运行；无运行时显示 0 次、成功率和耗时为 — |
| 会话列表 | 只展示指定 Agent 下本人会话；按所选窗口内最近运行倒序，有多种调用来源时显示混合来源 |
| 会话详情 | 按运行开始时间正序分页展示输入输出；默认加载最近一页；按 runId 打开时直接加载目标运行 |
| 知识库列表 | 展示当前文档及可用切片存量，不受历史时间窗口影响 |
| 知识库详情 | 文件处理记录和检索记录分别分页，受时间范围筛选影响；当前存量与历史次数分开展示 |
| 任务详情 | 按 taskId 展示该次处理的阶段和结果；切片使用该次快照，不读取最新文档切片冒充历史 |

保留现有 `/workspace/operations` 路由。当前文件详情路由中的 `documents/:id` 实际传 taskId，实施时在参数和类型中明确命名为 taskId，无需单独改路由。

### 4.2 筛选、分页与链接

- URL 保存 `range=24h|7d|30d`、`status`、`q`、`page`、`pageSize`、`sort`；知识库标签保存 `tab`。
- 会话详情使用 `run=<runId>&node=<nodeId>` 定位真实节点，不能仅用 knowledge/plugin 类别区分重复调用。
- 改变筛选条件重置页码为 1；返回列表恢复 URL 条件和已有滚动位置。
- 关键词去除首尾空白，最多 100 字；输入停止 300ms 后查询。搜索范围限定为对应列表的名称、标题和 ID，不默认全文搜索聊天正文。
- 前端可纠正不合法的展示参数；后端仍独立校验，不能依赖前端。
- 详情查询不继承列表时间限制。无权限与不存在统一显示“记录不存在或不可访问”。

### 4.3 加载、刷新和轮询

- 首次加载显示加载态；请求成功且结果为空才显示空态；失败显示错误与重试入口。
- 手动刷新重新请求当前页面数据。仅请求成功后更新“数据更新于”，失败保留旧数据并标记刷新失败。
- 页面存在 running/processing 记录时，每 5 秒刷新相关查询；请求未完成时不叠加下一次轮询。
- 页面隐藏、组件卸载或不再存在进行中记录时停止轮询；页面恢复可见后重新查询。
- 请求参数变化时取消旧请求或通过请求序号忽略旧结果。不同用户、不同筛选的缓存不得混用。
- 退出登录清空运行管理缓存。401 回到既有登录流程；网络或服务错误不转换成空数据。
- 耗时、Token、首字时间缺失显示“未采集”或 —；未知不是 0。

### 4.4 分层

`apps/web` 的 feature 层负责身份、路由、API、请求状态和 DTO 转换；`packages/ui` 通过 props 和回调展示数据。共享契约放入项目已有共享包，后端不依赖 UI 类型。

保留有价值的动画及导航行为。生产页面移除 Mock 注入；Mock 可继续作为测试 fixture，接口失败时不得自动回退为 Mock。

## 5. 指标口径

所有聚合在后端按同一用户和同一时间窗口计算，不能由当前页前端列表推算。

| 指标 | 规则 |
| --- | --- |
| 时间窗口 | 按 startedAt 过滤，使用 `[from, to)`；轮询时重新计算滚动窗口 |
| 今日 | Asia/Shanghai 当日 00:00 到下一日 00:00，查询前转 UTC |
| 运行次数 | 窗口内所有已创建 Run，包括运行中和取消 |
| 成功率 | `(success + warning) / (success + warning + failed)`；分母为 0 返回 null |
| 异常次数 | warning 单独统计，不能混淆成失败次数 |
| 取消次数 | cancelled 单列，不进入成功率分母 |
| 平均耗时 | success/warning/failed 且 durationMs 已知的样本；返回样本数，无样本为 null |
| 总耗时 | 后端受理本轮运行到最终回复及运行终态保存；采用单调时钟测量耗时 |
| 首字耗时 | 受理到收到首个非空 message.delta；非流式或未输出文本为 null |
| Token | 使用实际 usage，缺失为 null；累计值和峰值仅基于已采集样本，并返回已采集/未采集次数 |
| 检索命中率 | `hit / (hit + no_hit)`，失败另计；从未检索过不能计为 no_hit |
| 文档存量 | 当前文档数、当前 READY 文档的可用切片数；不受历史任务窗口影响 |
| 文件处理次数 | 每次 ProcessingTask 计一次，重试单列 attempt，不按文档数统计 |
| 文档字节数 | 原始上传字节或输入文本 UTF-8 字节数；切片字节按 UTF-8 内容统计，不包含向量存储 |

模型多轮工具调用的 usage 必须覆盖各轮。若只能获取部分轮次用量，标记 `usageCompleteness=partial`，不当作完整样本参与完整 Token 峰值统计；可以单列已知用量。Runtime 需要显式给出完整性，不能凭非空 usage 猜测。

上传耗时与后端处理耗时分开。未采集到上传过程时 uploadMs 为 null，不能通过 createdAt/updatedAt 相减构造；有任一未知项时总上传加处理耗时也为 null。

## 6. 数据结构设计

以下是逻辑字段，不是直接执行的 Prisma schema。数据库枚举可沿用项目的大写风格，通过 DTO 映射为 API 小写值。ID 复用现有资源类型；Run 使用当前 Runtime 的 UUID。

### 6.1 OperationRun

| 字段 | 类型/要求 |
| --- | --- |
| id | runId，主键，与 Runtime 请求一致 |
| userId、agentId、conversationId | 必填，userId 来自认证上下文 |
| userMessageId、assistantMessageId | 本轮消息引用，助手消息与运行一对一 |
| source | `platform/api`，由服务入口传入，不由终端用户声明 |
| agentName、model、revision | 执行时必要配置快照；不保存系统提示词或密钥 |
| status、cancelReason | 运行状态；取消原因可空 |
| startedAt、finishedAt、updatedAt | UTC 时间，未结束时 finishedAt 为 null |
| durationMs、firstTokenMs | 非负整数或 null |
| inputTokens、outputTokens | 非负整数或 null |
| usageCompleteness | `complete/partial/unavailable` |
| errorCode、errorMessage | 可空，面向用户的安全错误信息 |
| observationVersion | 采集结构版本，用于区分真实采集字段与历史缺失 |

问答正文复用 Message，不在运行表重复保存。列表返回限制长度的摘要，详情按归属校验后读取完整消息。

建议索引：`(userId, startedAt, id)`、`(userId, agentId, startedAt)`、`(userId, conversationId, startedAt)`；根据实际查询补充 status 索引，避免一次添加大量索引。

### 6.2 OperationNode

| 字段 | 类型/要求 |
| --- | --- |
| id、runId、parentId | 节点 ID、归属运行、可空父节点 |
| kind | `retrieval/model/tool` |
| sequence、externalCallId | 排序号；工具调用关联 Runtime toolCallId |
| status、startedAt、finishedAt、durationMs | 状态、时间与可空耗时 |
| errorCode、errorMessage | 可空错误 |
| detail | 按 kind 区分的有界 JSON，禁止无约束塞入完整原始事件 |

`(runId, sequence)` 唯一；工具开始和结束按 externalCallId 更新同一节点。所有写入必须验证节点归属，终态更新具有幂等性。

detail 按种类定义：

- retrieval：实际 query、请求知识库 ID、每库结果 `hit/no_hit/failed`、候选切片、分数和最终注入上下文的切片 ID。
- tool：toolName、toolCallId、脱敏且截断的 input/output、截断标记。
- model：本次模型调用名称、结束原因、已采集 usage；当前协议没有轮次事件时先不展示细分模型节点，不能从总耗时伪造。

检索候选保留 knowledgeBaseId、documentId、chunkId、标题、片段内容快照、score 和 `includedInContext`。回答明确提供的引用另存 `citedInAnswer`；无法判断时为 null，不能声称模型必然使用了某段内容。

单次检索可跨多个知识库：记录公共调用耗时；没有每库计时就不给每个库重复填相同耗时。未命中的库也保留结果，不能只保存命中切片导致记录缺失。

### 6.3 DocumentProcessingTask

字段：`id、userId、knowledgeBaseId、documentId、documentTitle、attempt、status、startedAt、finishedAt、processingMs、uploadMs、errorCode、errorMessage、stages、snapshot`。

- `(documentId, attempt)` 唯一，attempt 从 1 开始。
- stages 保存有限固定阶段的状态、开始结束时间和耗时，失败阶段的错误不被后续更新覆盖。
- snapshot 保存本次 sourceBytes、chunkCount、chunkBytes；失败且未产生成果时相应字段为 null。
- 文档创建与第一次任务创建在同一事务内完成；重试的状态抢占与新任务创建也在同一事务内完成。
- 同一文档同时只允许一个 processing 任务；通过数据库条件更新和唯一约束保证，不仅靠前端按钮或内存 Set。
- 只保存后端拥有的个人知识库任务，userId 由已认证身份及资源归属确定。

### 6.4 TaskChunk

字段：`id、taskId、sourceChunkId、position、content、startOffset、endOffset`。`(taskId, position)` 唯一。

只在成功入库时保存结果快照，不保存向量副本；与文档 READY 和任务 ready 在同一事务提交。重试生成新快照，旧成功任务仍指向自身内容。失败过程不持久化中间切片全文，详情提示“本次处理没有可用的切片快照”。

### 6.5 历史兼容

现有旧消息继续在聊天模块可见；首版不把旧消息批量包装成 Run。运行管理展示“自采集上线起的运行记录”。现有文档可以参与当前存量统计，但没有历史任务时展示“历史处理过程未采集”。

当前前端 `OperationsData` 全量数组不再作为生产查询契约；保留为 fixture 或逐页拆分。禁止为了兼容旧展示类型给未知 Token、阶段耗时填 0。

## 7. 后端接口契约

### 7.1 通用规则

- 前缀 `/api/operations`，全部要求登录 JWT；只读 GET。
- 不接收 userId/workspaceId 来决定权限，当前用户从现有认证上下文获取。
- 列表分页 `page` 默认 1，`pageSize` 默认 20、最大 100。
- 时间参数 `from/to` 使用 UTC ISO 8601，必须同时提供且 from < to；不传默认最近 30 天。单次列表窗口最长 30 天，允许查询任意历史 30 天窗口。
- 排序值使用各接口允许列表；默认 `startedAt_desc`，并以 id 作为稳定的第二排序键。
- 返回时间为 ISO 8601；耗时为毫秒，未知值返回 null。
- 成功响应沿用 ResponseInterceptor 的 `{ code: 200, message: "ok", data }`。
- 失败沿用现有 HTTP 异常过滤器的 `{ code, message, data: null }`，不新增另一套响应外壳。
- 400 参数不合法，401 未登录，404 不存在或不属于当前用户，500/503 服务错误。

分页 data 结构：

```ts
interface PageResult<T> {
  items: T[];
  page: number;
  pageSize: number;
  total: number;
  asOf: string;
}
```

asOf 表示本次查询完成时刻，不承诺跨页数据库快照。列表和本次 total/summary 在同一一致性读取中计算；翻页期间新记录可能使位置变化，刷新返回第一页。不引入长事务维持浏览器整个会话的快照。

### 7.2 接口清单

| GET 路径 | 查询参数 | data 内容 |
| --- | --- | --- |
| `/overview` | 无 | asOf、todayFrom/todayTo、今日 failed/warning 数量、累计已知 Token 与采集覆盖数、完整样本峰值 |
| `/events` | from/to、module=agent/knowledge、severity=failed/warning、q、sort、page/pageSize | 混合运行事件分页；eventType、资源 ID、状态、标题、开始时间、可空耗时与 Token |
| `/agents` | from/to、q、page/pageSize | Agent 元信息及窗口内 counts、successRate、averageDurationMs、durationSampleCount |
| `/agents/:id/conversations` | from/to、q、source、status、page/pageSize | 窗口内有运行的会话摘要、来源集合、各状态数量、lastRunAt |
| `/conversations/:id/runs` | page/pageSize | 会话运行摘要分页，默认最新在前；前端按消息顺序展示当前加载结果 |
| `/runs/:id` | 无 | 运行详情、问答正文、指标、节点数组及采集缺失说明 |
| `/knowledge-bases` | q、page/pageSize | 当前文档数、可用切片数、字节数、处理中与失败文档数 |
| `/knowledge-bases/:id/tasks` | from/to、status、q、page/pageSize | 处理尝试分页，包含文档摘要、attempt、状态和可空耗时 |
| `/knowledge-bases/:id/retrievals` | from/to、status=hit/no_hit/failed、page/pageSize | 检索节点分页、query 摘要、runId、conversationId、该库结果；另含整个过滤范围的命中/未命中/失败汇总 |
| `/tasks/:id` | 无 | 文档摘要、任务状态、阶段、错误、snapshot、是否具有历史切片 |
| `/tasks/:id/chunks` | page/pageSize | 本次成功任务的 TaskChunk，position 正序；无快照时空列表并附原因 |

`status` 在会话列表中表示“窗口内至少有一轮符合该状态”，不表示整段会话只有一个状态。会话展示失败数、异常数、运行中数，避免单个红色状态覆盖所有轮次的真实情况。

概览今日异常通过 `/events` 传入 overview 返回的今日边界和 severity 分别查询；如 UI 使用单个“异常”列表，增加明确的 `severity=abnormal`（failed 或 warning）枚举，不用前端拼两页数据。

详情中的资源标识由前端路由构造跳转；删除后的关联文档显示不可用，不使用非空断言造成整页崩溃。

### 7.3 写入入口

不提供让浏览器上报 Run 或修改状态的接口。运行记录由 ChatService、Runtime 事件消费与知识库处理服务内部写入。

Runtime 与 NestJS 的内部链路需要关联 runId、检索调用 ID 和 toolCallId，并保持现有身份授权校验。观测字段的扩充不向公开 API 暴露内部输入、检索全文或工具敏感数据。

## 8. 权限、隐私与删除

- 仅允许读取当前用户的运行、消息、文档和处理历史。列表、聚合、详情、切片都必须校验，知道 ID 不构成访问权限。
- Agent 列表以 ownerId 为当前用户过滤；会话同时验证 userId 和对应 Agent。知识库沿用实际个人归属规则，不能仅按传入 workspaceId 查询。
- 本地 ws-local-demo 的知识库不自动并入个人运行管理；不为新接口增加匿名 demo 绕过。
- 平台/API 来源按每次调用记录；不把 API Key 密钥保存到记录，必要时仅存其不可逆的关联标识。
- 工具参数按允许字段保存，认证头、Token、密码、Cookie 不进入记录；自由文本仍可能含个人信息，应仅本人可见。
- 工具输入与输出各限制 16 KiB UTF-8，安全截断并记录 truncated；检索快照沿用真实检索数量与上下文长度约束，不额外复制全库文本。
- 不重复存系统提示词、完整请求头、向量或无限长原始 SSE。异常展示使用安全错误信息，完整堆栈仅进入现有服务日志。
- 不自动定时清理不代表删除后仍保留敏感内容：删除会话时级联删除其 Run/Node；删除文档或知识库时删除对应 Task/TaskChunk，并清除运行节点中该资源的检索文本快照，保留无正文的“来源已删除”标记。
- 删除资源与历史清理应事务化；混合知识库检索仅清理被删资源片段，不删除其他来源。删除 Agent 沿用既有会话生命周期规则，不能借此次改造扩大删除范围。

## 9. 采集与一致性

### 9.1 聊天路径

1. 先完成身份、会话与 Agent 校验。未通过校验的请求不创建运行记录。
2. 生成 runId；将用户消息、助手消息和 running 记录一起创建。创建失败则不调用 Runtime。
3. 平台流式、API 流式、API 非流式显式传入 source，并共用持久化规则。
4. 消费事件时记录首字时间和节点，保留现有 runId、conversationId、seq 校验。不要每个文本 token 都写数据库。
5. 原始事件可以流式转发，但完成/失败终态仍必须在消息和 Run 状态落库后才能对客户端确认。
6. 终态更新采用条件 `status=running`，避免取消与完成竞态、迟到事件重复覆盖。
7. 最终消息与 Run 终态在同一事务保存。保存失败沿用 PERSISTENCE_FAILED 行为，不向客户端声明成功；记录带 runId 的服务日志。
8. 节点采集写入失败必须有可观察日志，并标记详情不完整；不得回滚已保存的用户回复，也不得用伪造节点填补。

非流式接口只能取得最终结果时，先保存能确认的 usage、引用和工具结果；首字及节点耗时为 null。后续扩充 Runtime 内部观测结果以补齐，不通过模拟 SSE 捏造时间。

### 9.2 知识库路径

1. 文档与第一次任务创建成功后再 schedule。
2. 每次阶段转换更新该任务的阶段记录，不通过文档 updatedAt 推导全部历史。
3. 成功时在一个事务内替换当前索引、保存该任务切片快照、设置文档 READY 和任务 ready。
4. 失败时更新文档和任务失败状态，保留具体阶段及安全错误。
5. 重试时原子抢占 FAILED 状态并创建下一 attempt；冲突返回既有 409。
6. 启动恢复时先将上个进程未完成的任务标为中断失败，再为需要恢复的文档创建新 attempt 后调度，避免把两次执行拼成一次耗时。

当前按单实例部署设计。进程退出后未结束的聊天 Run 在下一次启动时收敛为 failed，错误码可定义为 PROCESS_INTERRUPTED；未知完成时刻和耗时为 null，不拿重启时刻假装实际执行耗时。若以后扩成多实例，需要先增加执行归属、租约与抢占规则，不能直接全局扫描并终结其他实例任务。

| 1. 定义契约 | 共享类型、运行管理 DTO、Prisma schema 与迁移 | 固定状态、可空指标、分页和索引；验证旧消息/文档无需伪造回填 |
| 2. 接入聊天采集 | ChatService、公共 API 入口、Runtime 内部契约 | 三条调用路径均产生真实 Run，取消/失败/工具多次调用正确落库 |
| 3. 接入文档采集 | 创建、process、retry、启动恢复 | 每次尝试独立，任务和索引结果一致，重复重试被拒绝 |
| 4. 查询模块 | 新增 backend operations module/controller/service | 当前用户隔离、分页、统计、详情、脱敏和删除清理 |
| 5. 接入前端 | operations feature API/controller、UI props/model | 替换生产 Mock；刷新、筛选、状态、轮询、历史快照和真实节点定位 |
| 6. 联调验收 | 相关单测、数据库集成测试、页面流程 | 下面的验收场景全部通过，再移除“模拟数据”标记 |

按项目已有 pnpm 脚本和测试模式执行。先跑目标单测、类型检查，再运行涉及数据库的事务与权限验证；不为本功能升级框架或引入重量依赖。

如果 Runtime 精细节点采集尚未完成，可以先交付真实运行概要，但界面必须明确“过程未采集”，不能声称完整链路已接入。只有端到端验收完成才能声明整个功能完成。

## 11. 验收场景

| 场景 | 预期 |
| --- | --- |
| 平台成功聊天 | 一轮对应一条 Run，刷新仍可见，正文和终态一致 |
| API 流式/非流式 | 均有记录且 source=api；非流式首字为 null |
| 同会话混合来源 | 每轮来源正确，会话汇总为混合来源 |
| 连续多次工具调用 | 每次独立节点，顺序和 toolCallId 正确 |
| 工具失败后回答完成 | warning；保留失败节点，成功率与异常数符合口径 |
| 知识库未命中 | no_hit，不自动把 Run 标为失败 |
| 使用量缺失/部分缺失 | 不显示 0，不冒充完整样本，覆盖数正确 |
| 用户取消/连接中断 | 终态正确，保留已生成内容，迟到完成事件不覆盖 |
| 最终持久化失败 | 客户端不收到成功；日志可用 runId 定位 |
| 服务重启 | 旧运行不永久停留 running；文档恢复创建新 attempt |
| 文档失败后重试 | 两条任务，旧失败不消失，当前状态由新任务决定 |
| 重复重试提交 | 只有一条新 processing 任务，其余返回冲突 |
| 历史切片 | 旧任务显示自身快照，不随新处理结果变化 |
| 刷新失败/筛选竞态 | 保留旧数据并提示；旧请求不覆盖最新查询 |
| 分页统计 | 汇总覆盖整个过滤范围，不随 pageSize 改变 |
| 时间边界 | 自然日与滚动窗口正确，恰好在 to 的记录不计入 |
| 用户隔离 | 另一用户在列表、统计、详情、切片接口均无法访问 |
| 删除业务资源 | 敏感历史按规则清理，关联页面不会崩溃 |
| 旧数据 | 可查看现有业务数据；缺失的运行过程明确未采集 |

## 12. 完成标准

真实执行能够生成可持久化、可追溯、仅本人可读的运行记录；接口和前端采用统一统计口径；重试与取消不破坏历史；未知指标不伪造；关键事务、权限和故障路径均经过验证。

本节为完整历史采集阶段的完成标准，不代表该阶段已交付。当前实际实现和验证范围以第 0 节为准。
