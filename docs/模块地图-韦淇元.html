A · 地基

认证与用户

让人能进来，且每个接口都知道"现在是谁"
  • A1 User 数据模型
    Prisma User 表 + 首条 migrate
  • A2 用户名密码注册
    bcrypt 哈希，禁明文/MD5
  • A3 登录 + 签发 JWT
    有效期 7 天，不做 refresh
  • A4 JWT 守卫 + @Public()
    JwtAuthGuard / 公开接口标记
  • A5 CurrentUser 注入
    @CurrentUser() 装饰器
  • A6 401/403 错误格式
    过滤器已有，鉴权码未接
  • A7 Google OAuth
    可砍：网络不通先降级
  • A8 前端登录态
    页面壳已有，未接接口
验收条 1：注册→登录→读用户→退出
B · 容器

会话与历史

给聊天一个"盒子"，消息能存能翻
  • B1 Conversation / Message
    含 role、status、JSON 扩展列
  • B2 会话与消息接口
    创建 / 列表 / 历史（游标分页）
  • B3 归属校验
    越权 403/404，删除策略待定
  • B4 前端会话区 UI
    左侧列表 + 消息区 + 输入框
/app/chat 目前还是 ComingSoon 占位
C · 核心

流式对话（SSE）

送进 Runtime，一个字一个字吐回页面
  • C1 RuntimeClientService
    fetch + 流式解析，契约里有示例代码
  • C2 ChatService（唯一路径）
    网页与公开 API 共用，绝不复制两份
  • C3 网页流式接口
    /api/agents/:id/chat/stream
  • C4 中断生成
    abort → cancelled，保留 partial
  • C5 并发控制
    同会话 409 CONVERSATION_BUSY
  • C6 前端 SSE 消费
    打字机 + 停止 + 重试（不用 EventSource）
  • C7 本地 Mock Runtime
    .env 切 URL，不阻塞王一恒
验收条 2：网页 + 公开 API 同一条路径
D · 出口

发布与公开 API

Agent 发布出去，别人拿 Key 就能调
  • D1 发布动作与状态流
    draft → published，接口归属待定
  • D2 AgentConfig 快照
    发布时冻结 revision
  • D3 API Key 生成
    mk- 前缀，存哈希，只展示一次
  • D4 公开接口 + Key 守卫
    /v1/agents/:id/chat，Bearer
  • D5 公开流式一致性
    复用 C2，同一套 SSE 事件
  • D6 发布页 / 密钥管理
    TS SDK 归属待确认
验收条 3：密钥只放 .env

建议实现顺序（依赖不能反）

  1. E1 + E2：CurrentUser 类型 + 401/403 → 今天就能发群（全组等你）
  2. A1 → A6：User 表 → 注册 → 登录 → JWT → 守卫 → CurrentUser
  3. A8 + B1~B4：前端登录态 + 会话容器
  4. C7 → C1 → C2 → C3/C6：先 Mock 跑通，再接真实 Runtime
  5. C4/C5：中断 + 并发（细节，可后置）
  6. D3 → D4 → D5 → D1/D2/D6：Key 先行，发布流程收尾

时间不够时的砍法

  1. 先砍 A7 Google OAuth（降级 Week 3，验收时说明）
  2. 再砍 D5 公开 API 的 SSE（先出非流式 JSON 保底）
  3. 可选砍 D6 TS SDK（等组会确认归属）
  4. 不许砍：用户名密码登录、聊天页 + SSE、API Key + Bearer 鉴权
