# 后端登录实现方案（NestJS）

> 范围：A 认证与用户模块的**后端部分** —— 注册、登录、JWT 签发与校验、`CurrentUser` 获取、统一 401/403 错误格式。
> 不含：Google OAuth（A7，后置）、刷新 Token、邮箱验证、找回密码、API Key 鉴权（D 模块）。
> 版本：v1（2026-10-18）

---

## 1. 设计思路（先想清楚这 8 件事）

### 1.1 ORM 选型：建议 Prisma

| | Prisma | TypeORM |
| --- | --- | --- |
| 上手成本 | schema 是声明式 DSL，读起来像表结构；`prisma.user.findUnique({where})` 直观 | 装饰器 + Entity 类，概念多（Repository/DataSource/EntityManager） |
| 类型安全 | 生成的 Client 类型**跟着 schema 自动变**，改表立刻报错 | 手写 Entity，类型靠自觉 |
| Migration | `prisma migrate dev` 自动生成 SQL + 版本文件 | 可自动生成也可手写，配置多 |
| 参考仓库 | momo040611/MiniCoze 用的就是 Prisma，能直接抄 | — |

结论：**用 Prisma**。你 TS 不熟，Prisma 的报错和自动补全能省掉一半踩坑时间。

> ⚠️ **这是全组公共决策**。`prisma/schema.prisma` 是所有人共用的（会话表、Agent 表、知识库表都要往里加）。动手前在群里说一句：
> 「我准备用 Prisma 建 User 表，schema 放 `apps/backend/prisma/schema.prisma`，大家的表都往这个文件加，我来维护初始化。」

### 1.2 表设计：先只建 User

```prisma
model User {
  id           String   @id @default(uuid()) @db.Uuid
  email        String   @unique
  passwordHash String
  displayName  String
  avatarUrl    String?
  createdAt    DateTime @default(now())
  updatedAt    DateTime @updatedAt
}
```

要点：
- `id` 用 **uuid**。记忆里已定「`actor.id` 恒为用户表主键」，uuid 比自增 ID 安全（不暴露用户量、公开 API 场景不泄漏）。
- **只存 `passwordHash`，永不存明文密码**，也永不把 `passwordHash` 返回给前端。
- 后续 `Conversation` / `Message` / `Agent` 表由对应负责人追加，你先别替他们建。

### 1.3 模块边界：三个模块 + 一个 common

```
PrismaModule (@Global)     —— 只有它持有 PrismaClient，全app注入即用
UsersModule                —— 用户读写，别的模块（Agent/知识库）也要用，独立出来
AuthModule                 —— 注册/登录/me，持有 JwtStrategy
common/                    —— Guard、装饰器、错误体系（全组公共，横向最优先）
```

为什么 `UsersModule` 要独立？因为陈弘毅（Agent）、管逸恬（知识库）后面都要「按 userId 查用户信息 / 校验归属」，如果只有 `AuthService` 能查用户，他们就得反向依赖你的 auth 模块，耦合会很脏。

### 1.4 认证形态：JWT Bearer，MVP 不做 Refresh

- 登录成功返回 `accessToken`，前端存 `localStorage`，请求头带 `Authorization: Bearer <token>`。
- 有效期 **7 天**（MVP 够用，演示不会中途掉线）。
- **不做 refresh token**：多做一张表 + 一套轮换逻辑，性价比低。真要加，后期加 `RefreshToken` 表即可，不影响现有契约。
- 为什么不用 Session/Cookie：浏览器 5173、后端 3000 跨端口，Cookie 要处理 SameSite/CORS；JWT 对后面的**公开 API（D 模块）**也更友好。

### 1.5 密码哈希：bcryptjs

用 `bcryptjs` 而不是 `bcrypt`：`bcrypt` 是原生模块，Windows 上要 node-gyp 编译，你这台机器大概率装不上；`bcryptjs` 纯 JS，装完就能跑。cost = 10。

### 1.6 统一错误码（这是 E2 契约，要发群）

现在 filter 只返回 `message`，前端没法判断「到底是没登录还是没权限」。定成：

```json
{
  "statusCode": 401,
  "code": "TOKEN_INVALID",
  "message": "登录凭证无效或已过期",
  "path": "/api/agents",
  "timestamp": "2026-10-18T10:00:00.000Z"
}
```

规则（写死，全组遵守）：
- **401** = 没带 token / token 失效或过期 → `code` 为 `TOKEN_MISSING` / `TOKEN_INVALID` / `INVALID_CREDENTIALS`
- **403** = token 有效但资源不属于你 → `code` 为 `FORBIDDEN`
- 前端判断：`res.status === 401` 就清 token 跳登录页；`403` 就提示无权限，**不要**跳登录。
- 内部服务（Runtime 等）的 401 **不得**当成用户登录失效透传，按已定契约映射成 `RUNTIME_UNAVAILABLE`(503)。

### 1.7 `CurrentUser` 进 `@minicoze/shared`（这是 E1 契约，要发群）

```ts
export interface CurrentUser {
  id: string;
  email: string;
  displayName: string;
  avatarUrl?: string;
}
```

它是全组最上游的契约：Runtime 请求的 `actor.id`、会话归属校验、前端 Header 展示，全用它。**冻结后就别乱改字段**，要加字段先群里说。

### 1.8 明确不做（写下来，防止自己跑偏）

- ❌ Google OAuth（A7，优先级最低，砍需求时第一个砍）
- ❌ 刷新 Token / 登出黑名单（JWT 无状态，前端丢弃即登出）
- ❌ 邮箱验证码、找回密码
- ❌ 角色权限系统（RBAC）—— MVP 只有「是不是你自己的资源」这一层判断

## 2. 数据流

**注册**
```
POST /api/auth/register {email,password,displayName}
  → ValidationPipe 校验 DTO
  → 邮箱转小写，查重 → 已存在抛 409 EMAIL_ALREADY_REGISTERED
  → bcryptjs.hash(password, 10)
  → prisma.user.create()
  → 签发 JWT → 返回 {accessToken, user}
```

**登录**
```
POST /api/auth/login {email,password}
  → 按邮箱查用户 → 查不到抛 401 INVALID_CREDENTIALS
  → bcryptjs.compare(明文, hash) → 不匹配抛同一个 401
  → 签发 JWT → 返回 {accessToken, user}
```
> 查不到用户和密码错**返回同一个错误**，避免攻击者用错误信息枚举哪些邮箱注册过。

**访问受保护接口**
```
GET /api/auth/me  Header: Authorization: Bearer xxx
  → JwtAuthGuard → passport-jwt 校验签名+过期
      失败 → 401 TOKEN_INVALID
  → validate() 把 {id,email} 挂到 request.user
  → Controller @CurrentUser() 取到 → 回库查最新资料 → 返回 CurrentUser
```

**改造** `apps/backend/src/common/http-exception.filter.ts`（替换整个文件）：

```ts
import {
  ArgumentsHost,
  Catch,
  ExceptionFilter,
  HttpException,
  HttpStatus,
} from '@nestjs/common';
import type { Request, Response } from 'express';
import { DEFAULT_CODE_BY_STATUS, ErrorCode } from './errors/error-codes';

interface ErrorResponse {
  statusCode: number;
  code: string;
  message: string | string[];
  path: string;
  timestamp: string;
}

@Catch()
export class HttpExceptionFilter implements ExceptionFilter {
  catch(exception: unknown, host: ArgumentsHost) {
    const context = host.switchToHttp();
    const response = context.getResponse<Response>();
    const request = context.getRequest<Request>();

    const status =
      exception instanceof HttpException
        ? exception.getStatus()
        : HttpStatus.INTERNAL_SERVER_ERROR;

    const exceptionResponse =
      exception instanceof HttpException ? exception.getResponse() : undefined;

    const payload =
      typeof exceptionResponse === 'object' && exceptionResponse !== null
        ? (exceptionResponse as Record<string, unknown>)
        : undefined;

    const message =
      payload && 'message' in payload
        ? (payload.message as string | string[])
        : exception instanceof HttpException
          ? exception.message
          : '服务内部错误';

    const code =
      payload && typeof payload.code === 'string'
        ? payload.code
        : (DEFAULT_CODE_BY_STATUS[status] ?? ErrorCode.INTERNAL_ERROR);

    const body: ErrorResponse = {
      statusCode: status,
      code,
      message,
      path: request.url,
      timestamp: new Date().toISOString(),
    };

    response.status(status).json(body);
  }
}
```

新建 `apps/backend/src/auth/auth.service.ts`：

```ts
import { Injectable } from '@nestjs/common';
import type { JwtSignOptions } from '@nestjs/jwt';
import { JwtService } from '@nestjs/jwt';
import type { AuthResponse, CurrentUser } from '@minicoze/shared';
import { compare, hash } from 'bcryptjs';
import { AuthErrors } from '../common/errors/business.exception';
import { UsersService } from '../users/users.service';
import { LoginDto } from './dto/login.dto';
import { RegisterDto } from './dto/register.dto';

const SALT_ROUNDS = 10;

/** token 里只放这两样，别塞敏感信息（JWT 只是 base64，谁都能解开看）。 */
export interface JwtPayload {
  sub: string;
  email: string;
}

@Injectable()
export class AuthService {
  constructor(
    private readonly usersService: UsersService,
    private readonly jwtService: JwtService,
  ) {}

  async register(dto: RegisterDto): Promise<AuthResponse> {
    const email = dto.email.trim().toLowerCase();

    const existing = await this.usersService.findByEmail(email);
    if (existing) {
      throw AuthErrors.emailTaken();
    }

    const passwordHash = await hash(dto.password, SALT_ROUNDS);
    const user = await this.usersService.create({
      email,
      passwordHash,
      displayName: dto.displayName.trim(),
    });

    return this.issueToken(user);
  }

  async login(dto: LoginDto): Promise<AuthResponse> {
    const email = dto.email.trim().toLowerCase();

    const user = await this.usersService.findByEmail(email);
    // 用户不存在和密码错误返回同一个错误，避免被拿来枚举注册邮箱。
    if (!user) {
      throw AuthErrors.invalidCredentials();
    }

    const matched = await compare(dto.password, user.passwordHash);
    if (!matched) {
      throw AuthErrors.invalidCredentials();
    }

    return this.issueToken(user);
  }

  /** 用 token 里的 id 回库查最新资料，用户已被删除时返回 401。 */
  async getCurrentUser(userId: string): Promise<CurrentUser> {
    const user = await this.usersService.findById(userId);
    if (!user) {
      throw AuthErrors.invalidCredentials();
    }
    return this.usersService.toCurrentUser(user);
  }

  private async issueToken(user: {
    id: string;
    email: string;
    displayName: string;
    avatarUrl: string | null;
  }): Promise<AuthResponse> {
    const payload: JwtPayload = { sub: user.id, email: user.email };
    const accessToken = await this.jwtService.signAsync(payload);
    return { accessToken, user: this.usersService.toCurrentUser(user) };
  }
}
```

新建 `apps/backend/src/auth/jwt.strategy.ts`：

```ts
import { Injectable } from '@nestjs/common';
import { ConfigService } from '@nestjs/config';
import { PassportStrategy } from '@nestjs/passport';
import { ExtractJwt, Strategy } from 'passport-jwt';
import { JwtPayload } from './auth.service';

@Injectable()
export class JwtStrategy extends PassportStrategy(Strategy) {
  constructor(config: ConfigService) {
    super({
      jwtFromRequest: ExtractJwt.fromAuthHeaderAsBearerToken(),
      ignoreExpiration: false,
      secretOrKey: config.getOrThrow<string>('JWT_SECRET'),
    });
  }

  /** 返回值会被挂到 request.user，也就是 @CurrentUser() 拿到的东西。 */
  async validate(payload: JwtPayload) {
    return { id: payload.sub, email: payload.email };
  }
}
```

import type { ExecutionContext } from '@nestjs/common';
import { Injectable } from '@nestjs/common';
import { AuthGuard } from '@nestjs/passport';
import { AuthErrors } from '../errors/business.exception';

/**
 * 所有需要登录的接口都挂这个 Guard。
 * 别的模块直接用：@UseGuards(JwtAuthGuard)
 * 只需 AuthModule 在 AppModule 里注册一次（passport 策略是全局注册的）。
 */
@Injectable()
export class JwtAuthGuard extends AuthGuard('jwt') {
  handleRequest<TUser>(
    err: unknown,
    user: TUser | false,
    _info: unknown,
    _context: ExecutionContext,
  ): TUser {
    if (err || !user) {
      throw AuthErrors.invalidToken();
    }
    return user;
  }
}
```

export interface AuthPrincipal {
  id: string;
  email: string;
}

/** @CurrentUser() user  →  拿到 { id, email } */
export const CurrentUser = createParamDecorator(
  (_data: unknown, ctx: ExecutionContext): AuthPrincipal => {
    const request = ctx.switchToHttp().getRequest<{ user?: AuthPrincipal }>();
    return request.user as AuthPrincipal;
  },
);
```

新建 `apps/backend/src/auth/auth.controller.ts`：

```ts
import { Body, Controller, Get, HttpCode, HttpStatus, Post, UseGuards } from '@nestjs/common';
import type { AuthResponse, CurrentUser as CurrentUserPayload } from '@minicoze/shared';
import { CurrentUser } from '../common/decorators/current-user.decorator';
import { JwtAuthGuard } from '../common/guards/jwt-auth.guard';
import { AuthService } from './auth.service';
import { LoginDto } from './dto/login.dto';
import { RegisterDto } from './dto/register.dto';

@Controller('auth')
export class AuthController {
  constructor(private readonly authService: AuthService) {}

  @Post('register')
  @HttpCode(HttpStatus.CREATED)
  register(@Body() dto: RegisterDto): Promise<AuthResponse> {
    return this.authService.register(dto);
  }

  @Post('login')
  @HttpCode(HttpStatus.OK)
  login(@Body() dto: LoginDto): Promise<AuthResponse> {
    return this.authService.login(dto);
  }

  /** 前端启动 / 刷新页面时用它恢复登录态，也是验证 token 是否有效的标准接口。 */
  @Get('me')
  @UseGuards(JwtAuthGuard)
  me(@CurrentUser() user: CurrentUserPayload): Promise<CurrentUserPayload> {
    return this.authService.getCurrentUser(user.id);
  }
}
```

> 注意 `CurrentUserPayload` 这个别名：装饰器 `CurrentUser`（值）和 shared 里的 `CurrentUser`（类型）同名，用 `as` 别名避开冲突。全组统一用这个写法。

curl http://localhost:3000/api/auth/me

## 6. 容易踩的坑（提前看一眼）

1. **`pnpm` 下改了 `prisma/schema.prisma` 必须重新 `pnpm db:generate`**，否则 Client 里没有新字段，TS 直接报红。
2. **`passwordHash` 永远不要出现在任何返回值里**。所有对外返回都必须过 `toCurrentUser()` 这道闸门。
3. **JWT_SECRET 别硬编码**，也别提交到仓库。`.env` 已在 .gitignore 里，提交前 `git status` 看一眼。
4. **不要自己写 crypto 加密密码**，一律用 bcryptjs。
5. **别在 token 里塞 displayName/头像**：JWT 是 base64 不是加密，改昵称后 token 里的信息就过期了。`me` 接口回库查才是最新的。
6. **schema.prisma 是公共资产**，别人加了表你 `git pull` 后要重新 `pnpm db:generate` + `prisma migrate deploy`。
7. 全局 `ValidationPipe` 开了 `whitelist: true`，DTO 里没写装饰器的字段会被**静默丢弃**（不是报错），调试时别以为是前端没传。
